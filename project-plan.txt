BISUM Conference Website Project Documentation
1. Introduction & Project Goal
This documentation outlines the architecture, technology stack, and structure for the development of an annual conference event website. The primary goal of this project is to create a secure, user-friendly, and scalable platform that facilitates online attendee registration and payment processing. The website will serve as the central hub for all conference-related information, including schedules, speaker bios, and venue details.

2. Core Website Features
The website will offer the following key functionalities to attendees:
Homepage: An engaging landing page providing a high-level overview of the conference, including dates, location, and a call-to-action for registration.
Detailed Information: Dedicated sections for conference schedule, speaker profiles, and venue details.
Secure Registration Form: A simple, single-page form for attendees to provide their information and select a ticket type.
Online Payment Integration: Seamless and secure payment processing via Flutterwave.
Automated Email Confirmation: Attendees will receive an automated email with their registration details and receipt upon successful payment.
Admin Dashboard: A private, password-protected section for conference organizers to view, search, and manage registered attendees and their payment status.


3. Chosen Technology Stack
The project will be built using a modern, decoupled web architecture to ensure flexibility and scalability.

Frontend:
React.js: A JavaScript library for building a dynamic and responsive Single-Page Application (SPA).
Tailwind CSS: A utility-first CSS framework for rapid and consistent styling.
Axios: A promise-based HTTP client for making API requests to the backend.
Formik & Yup: Libraries for streamlined form creation and validation.

Backend:
Node.js: A JavaScript runtime environment for building a fast and scalable server-side application.
Express.js: A minimalist web framework for Node.js, providing robust features for a RESTful API.
Mongoose: An Object Data Modeling (ODM) library for MongoDB and Node.js, simplifying data schema and validation.
Flutterwave SDK: The official library for securely initiating and verifying payments.
Nodemailer: A module for sending emails from the Node.js application.
dotenv: To manage environment variables securely.

Database:
MongoDB: A NoSQL document database. This offers a flexible schema, ideal for storing attendee information without rigid table structures.

Deployment & Hosting:
Namecheap (cPanel): The hosting platform.
cPanel Node.js Selector: The tool used to deploy and manage the Node.js backend application.
Subdomain: The website will be hosted on a subdomain of the organization's main website (e.g., conference.organization.com).


4. Project Outcomes
Upon completion, the project will deliver:
A fully functional and responsive conference website.
A streamlined, secure attendee registration process.
A robust backend API for managing registration and payment logic.
A scalable database capable of storing a large number of attendee records.
A secure and efficient system for event organizers to manage attendee data.
5. Project Structure
The project will be structured into two main directories: client for the React frontend and server for the Node.js backend.
/conference-website/
├── client/
│   ├── public/                 // Static assets (index.html, images, etc.)
│   ├── src/
│   │   ├── components/         // Reusable React components
│   │   ├── pages/              // Top-level page components (Home, Register, Schedule, etc.)
│   │   ├── services/           // API service files (e.g., api.js for Axios)
│   │   ├── App.js              // Main component
│   │   ├── index.css           // Tailwind CSS build output
│   │   └── index.js            // React entry point
│   ├── package.json
│   └── tailwind.config.js
│
└── server/
    ├── node_modules/
    ├── models/                 // Mongoose data models (e.g., Attendee.js)
    ├── routes/                 // Express API routes (e.g., registrationRoutes.js)
    ├── controllers/            // Route logic (e.g., registrationController.js)
    ├── config/                 // Database and other configurations
    ├── .env                    // Environment variables
    ├── server.js               // Main Node.js/Express application entry point
    └── package.json

6. Page and Page Section Breakdown

Homepage
Header/Navigation: Main navigation menu (Home, Schedule, Speakers, Register).
Hero Section: Large, eye-catching banner with the conference name, dates, and a call-to-action button to register.
About Section: A brief overview of the conference's purpose and key themes.
Keynote Speakers Section: A carousel or grid of featured speakers with their photos and names.
Testimonials/Sponsors Section: Showcase of past attendees' feedback and conference sponsors.
Footer: Links to social media, contact information, and privacy policy.

Schedule Page
Header: Page title "Conference Schedule".
Agenda: A collapsible timeline or calendar view of sessions, including session titles, times, and speakers.


Speakers Page
Header: Page title "Speakers".
Speaker Grid: A grid of all speakers. Each speaker card will include a photo, name, and bio, which can be viewed in a pop-up modal on click.


Registration Page
Header: Page title "Register".
Registration Form: A single form requesting the following attendee information:
First Name
Last Name
Email Address (must be unique)
Phone Number
How you heard about Bisum (e.g Church, Flyer, social media, friend’s recommendation, etc)
Employment status (e.g., Student, working class, business owner)
Expectations for the conference
Payment Section: This will be handled by a secure redirect to Flutterwave's hosted payment page.

Admin Dashboard (Protected)
Login Page: A simple form for the administrator to log in.

Dashboard View:
Overview: A quick stat of attendance and payment, recent registration
Attendee List: A sortable and searchable table of all registered attendees.
Details View: On clicking an attendee, a detailed view shows their information and payment status.
Payment Detail: A sortable and  well-structured  detail calculation of every payment per day, month and categories
This part will be developed separately with a secure login and authentication system for the admin user.
